# 0004 — Go, with pure-Go dependencies

Date: 2026-11-01. Status: accepted.

## Context

Candidates evaluated: Go, Rust, TypeScript, Haskell, Zig. The project is an
IO-bound glue daemon that must run unattended for years, plus a protocol
library, a simulator, and an embedded web UI — with two deferred paths that
reward portability: the daemon on a rooted ARMv7 Android phone, and the
core embedded in a mobile app (gomobile).

## Decision

Go, with a **pure-Go dependency policy** (no cgo; e.g. `modernc.org/sqlite`
instead of bindings).

Decisive: the Prometheus ecosystem (client_golang is the reference
implementation), single static binaries with the UI via `embed.FS`, trivial
cross-compilation (an ARMv7 binary runs as-is on a rooted Android phone),
mature Nix packaging (`buildGoModule`), natural fit for "one goroutine owns
the TCP connection, channels fan telemetry out", and the smallest learning
curve among the candidates of interest.

Runners-up, for the record: Haskell (expressiveness, parser-combinator joy;
loses the phone paths — GHC on ARMv7 Android is heroics), Rust (best
embedding story; cost not justified for IO-bound glue), TypeScript (best
app-embedding reuse; weakest deployment story, no enthusiasm), Zig
(wonderful cross-compilation; pre-1.0 churn and ecosystem gaps in exactly
the places this project needs — metrics, HTTP, web).

## Consequences

- iOS embedding stays possible via `gomobile bind` but requires macOS/Xcode
  to build — acceptable; it was never the primary path.
- Domain modeling is plainer than in Haskell/Rust; accepted trade.
- The no-cgo rule is a hard constraint on dependency choices.
