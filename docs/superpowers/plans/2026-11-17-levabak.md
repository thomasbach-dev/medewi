# levabak Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An offline tool, `levabak`, that checks, shows and diffs the leva! settings backups (`MCu` menu dump, `MCm` EEPROM image), plus the daemon/medewictl changes that make every new backup trustworthy and self-describing.

**Architecture:** A pure package `backup/` (parse, check, layout, diff, file resolution) used by `cmd/levabak` and by the daemon's dump completeness check. `cmd/levabak` mirrors `cmd/levalog`'s shape (pflag, per-subcommand help, `--format text|jsonl|csv`). medewictl gains `--note`; the daemon refuses damaged MCu dumps and labels dumps ISO-8859-1.

**Tech Stack:** Go (pure, no cgo), `spf13/pflag`, standard library (`encoding/csv`, `encoding/json`, `text/tabwriter`, `encoding/hex`).

**Spec:** [docs/superpowers/specs/2026-11-16-levabak-design.md](../specs/2026-11-16-levabak-design.md) — read it first; this plan argues from it.

## Global Constraints

- Pure Go, no cgo. CLI per [docs/cli-conventions.md](../../cli-conventions.md): pflag `--long`, exit codes 0 ok / 1 read error or `check` problem / 2 usage, errors as `levabak: message` on stderr. `diff` exits 0 whether or not things differ.
- Tests use **synthetic** dumps with **invented** menu labels (`Alpha...`, `| Gain     1.0%`). The only real menu paths allowed in committed code are the layout table's `MCuPath`s: `PID 1/Kc`, `PID 1/Ti`, `PID 1/Td`, `PID 1/WU limit`, `Profiles/Use`. No real dumps, no license key, no private hostnames or paths in the repo.
- Dumps are Latin-1; levabak converts to UTF-8 on read, all output is valid UTF-8. The daemon keeps backup bodies byte-identical to the machine's reply.
- MCu line rule: `"| "` × depth + a 15-character cell, length 15 + 2·depth; a cell whose trimmed text ends in `...` is a menu.
- MCm: data records contiguous from 0x0000, checksums valid, end record `:00000001FF` or `:00000001F` last and nowhere else. Multi-byte values little-endian.
- File names: `TIMESTAMP_FIRMWARE[_NOTE].KIND`, TIMESTAMP `2006-01-02T150405Z` (UTC), KIND `mcu.txt` or `mcm.hex`; FIRMWARE never contains `_`.
- Output columns (jsonl keys = csv headers): check `src note line kind problem`; show `src note line path label value raw`; show --eeprom `src note offset type raw value name confidence`; diff `section key a b note`; layout `firmware offset type scale name confidence evidence`. Offsets print as `0x0173`.
- Commits: `git -c commit.gpgsign=false commit`, conventional commits, message ends with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and
  `Claude-Session: https://claude.ai/code/session_01BwcWPWKxrX9T3JcsdXWY4k`.
  Run `nix develop --command gate` before every commit; `nix flake check -L` before committing `flake.nix` changes. `git add` new files before the gate.

## Review Focus

1. **CRLF and trailing blank lines** in an MCu or MCm file (machine CRLF, medewictl's final `\n`) must not count as problems — test in Task 1 and Task 2.
2. **Non-backup files in a backup directory** (`.medewictl-*.tmp` left by an interrupted `writeAtomic`, a `README`, editor backups) are skipped with one note, never a failure — test in Task 4.
3. **Firmware `unknown`** (medewictl's name when the header is missing) or a firmware with no layout: one warning, `diff` still shows raw EEPROM bytes — test in Task 3 and Task 6.
4. **`°` and other Latin-1 bytes** reach csv/jsonl as valid UTF-8 (`8.8%/°`, not `8.8%/\xb0`) — test in Task 5.
5. **A `--note` with spaces, slashes or dots** (`post autotune/v2`, `..`) yields one safe file-name component, never a subdirectory or traversal — test in Task 8.
